Telegram

机器人 Token 与目标 Chat ID

  1. 创建自己的机器人。在 Telegram 找到官方 @BotFather，发送 /newbot，按提示设置名称与用户名，保存返回的 Bot Token。
  2. 让机器人能向你发送消息。私聊机器人并点击“开始”；群聊则将机器人加入目标群，确认允许发送消息。
  3. 获取目标 Chat ID。现有配置可直接沿用页面中的 ID。新建、尚未接入任何程序或 webhook 的机器人，可先给它发一条消息，再在自己的浏览器打开 https://api.telegram.org/bot<你的Token>/getUpdates，读取返回的 message.chat.id。群 ID 通常为负数，需完整复制。
  4. 填写并保存。把 Token 与 Chat ID 填入通知配置，开启需要的持仓卡片、加减仓或平仓提醒，保存后等待“配置已生效”。

已接入其他程序的机器人不要另开 getUpdates 轮询，也不要删除 webhook。用户名不能代替私人 Chat ID；公开超级群或频道可通过官方 getChat 查询已知目标。Token 留空会保留服务器原值。

收不到消息时检查什么？

确认已点击开始、机器人未被移出或禁言、Chat ID 属于正确目标。若更换机器人或群组，程序会建立新消息状态，避免编辑旧目标中的持仓卡片。网页保存只验证格式，不会自动发送测试消息。

Discord

目标文字频道的 Webhook

  1. 找到服务器集成设置。进入要接收通知的 Discord 服务器，打开“服务器设置 → 集成”。需要拥有管理 Webhook 的权限。
  2. 创建 Webhook。新建 Webhook，为它设置名称并选择接收消息的文字频道。每个 Webhook 都对应明确的发送位置。
  3. 复制完整地址。点击“复制 Webhook URL”。地址通常类似 https://discord.com/api/webhooks/编号/凭据，整段都需要保密，不要添加 /github 后缀。
  4. 设置持仓消息。在通知配置中启用 Discord，填入完整地址，选择持仓卡片和额外交易提醒，保存并等待生效。

持仓卡片更新原有消息，不会按刷新频率连续发送新消息。平台限流时会自动等待，设置 1 秒不代表每秒一定完成编辑。

Webhook 被删除或没有权限怎么办？

确认目标频道存在、Webhook 未被删除。重新创建后在网页填写新地址并保存。地址留空表示保留；关闭通道会保留已有凭据。如果只是恢复原 Webhook 的权限、地址没有变化，请先关闭 Discord 并保存、等待生效，再开启并保存，让通知重新连接。没有修改的保存不会重启通知。

Bark

手机开仓提醒与自定义铃声

  1. 打开手机 Bark。允许系统通知。使用自建服务时，先在 Bark 中添加并选择对应服务器，完成设备注册。
  2. 拆分个人推送地址。例如 https://push.example.com/DEVICE_KEY/测试内容：服务器地址是 https://push.example.com，设备 Key 是 DEVICE_KEY，不要复制后面的测试内容。
  3. 填写本项目的配置。服务器地址与设备 Key 分开填写。当前服务器上的 Bark 可以使用已配置的本机地址；手机端注册服务器必须与 Key 对应。
  4. 选择提醒方式。设置声音名称、通知分组、持续响铃开关与成交核对间隔，保存后等待生效。

本项目的 Bark 用于开仓方向成交提醒；不是持仓看板，也不发送平仓通知。不同服务器注册的设备 Key 不应混用。关闭期间的旧成交不会在重新启用后集中补发。

声音或推送没有出现怎么办？

检查手机通知权限、专注模式、Bark 当前服务器以及设备 Key。自定义声音需要先在 Bark 中导入，名称应与导入后的名称一致。网页显示接口接受，只表示推送服务接受请求，不代表手机已展示或已读。

Bitget 账户连接

现有账户已接入，通知配置无需重建 API

  1. 需要新账户时再创建 API。登录 Bitget 的 API 管理，创建 API Key，设置并保管 Passphrase，保存 Key、Secret 和 Passphrase 三项。
  2. 选择只读权限。监控读取账户、持仓与历史记录，无需开启交易、划转或提现权限。可将允许访问的 IP 绑定为服务器实际出口 IP。
  3. 由服务器管理员更换连接。账户凭据保存在项目的 config/.env，对应 BITGET_API_KEY、BITGET_API_SECRET、BITGET_API_PASSPHRASE。本网页仅开放通知渠道管理。
  4. 核对账户模式。经典账户与统一账户使用不同 API；应按实际账户模式配置并验证持仓同步。不要为了获取数据而开启交易权限。

网页只展示账户与持仓，不提供买卖下单。变更账户前请先保留原配置与业务数据，避免不同账户的历史记录混用。

读懂页面上的状态

把保存、加载和投递三个阶段分开看

“已保存”表示配置已写入服务器；“配置已生效”表示监控加载新配置并完成一次同步；“最近接口确认”来自通知平台的响应，不代表设备已读。通道关闭时保留密钥，重新开启不集中补发停用期间旧事件。修改同一份配置发生冲突时，页面会要求重新读取，保护其他页面刚保存的更改。
